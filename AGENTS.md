# Clipping Guide

Read docs/publishing-playbook.md before content, monitoring, or deployment work.

- Keep this an original, independent, practical resource for video clippers. Read real sources and callers before changing behavior. Prefer simple existing patterns and standard-library capabilities.
- Do not fabricate authors, credentials, tool testing, results, earnings, endorsements, rankings, or source access. Clearly distinguish examples from observations and vendor claims from established facts.
- New guides need distinct reader value, clear source attribution, real dates, and contextual internal links. Avoid copied transcripts, assets, outlines, and thin video rewrites.
- Preserve public URLs, content, accessibility, analytics behavior, and machine-readable guide access. For a changed route, add a deliberate redirect and verify it.
- Verify with the existing type checks, meaningful calculator tests, build, static content audit, and proportionate rendered UI checks. Do not add tests that simply mirror markup.
- Canonical branch is main; relevant verified fixes and authorized original content updates should be published and deployed to the existing Vercel project, then checked live.
- Preserve unrelated work. Keep credentials and local Vercel configuration out of Git and tool output. Never change a paid plan without a specific user request.
- Use the public creator RSS feeds and handled ledger for recurring checks. Do not mark a publication handled before its live verification. Source-fetch errors are not evidence of no updates.
- No messages to creators, communities, or other people are authorized by the blog-maintenance task.
